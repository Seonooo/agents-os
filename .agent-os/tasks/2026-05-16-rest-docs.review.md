## 2. Human Review — AFTER (2026-05-16 교정)

### 🔴 Major correction — Snippet 범위 확대 (R2)

> "e2e 테스트가 있다면 모두 문서화를 하는게 맞지 않을까?"

**잠정안의 "5 endpoint happy paths"를 "모든 29개 E2E 테스트"로 확장.**

#### 사용자 의도 (implicit)
**Tests-as-docs 철학**. 테스트가 검증하는 모든 관찰 가능 동작은 문서화 가치가 있음. happy path만 문서화하면 24개의 검증된 failure-mode가 클라이언트에 invisible해짐.

#### Cascading effects (도미노)
1. **스니펫 수**: 5 → **29** (~6배)
2. **스니펫 ID 컨벤션 확장**: `post-{action}` (5개) → `post-{action}-{case}` (e.g., `post-create-happy`, `post-create-missing-author`, `post-create-whitespace-title`, ...). R5의 잠정 컨벤션을 case suffix로 일반화.
3. **`index.adoc` 구조**: endpoint별 그룹핑 + happy/failure 서브섹션. 길어지지만 가독성 유지를 위해 endpoint별 `==` 헤더 + 케이스별 `===` 서브헤더.
4. **공유 helper 필요**: `ErrorResponse` 필드 descriptor가 16개 error 테스트(POST 6 + PUT 6 + 4 not-found)에 반복 → `errorResponseFields()` 공유 메서드로 추출.
5. **구현 phase 수**: 5 endpoint × 다수 테스트 = **6 phase** (infrastructure + POST 7 tests + GET list 7 + GET-by-id 4 + PUT 7 + DELETE 4 + index.adoc 통합).
6. **HTML 출력 길이**: 약 6배. 그러나 endpoint별 ToC로 탐색 가능.
7. **AC 확장**: snippet 검증을 "5개" → "29개 디렉터리 + 각 디렉터리 안에 ≥4개 .adoc 파일".

## 5. Learning notes

- **사용자가 보수적 잠정안을 확장하는 패턴 반복 관찰** — Week 1-2의 페이지네이션, PUT/DELETE의 soft delete, 이번 REST Docs 범위. 3회 같은 방향의 교정. AI 잠정안이 일관되게 underscope 되는 경향. 다음 task 잠정안 작성 시 "보수적이 아닌 도메인 표준 행동을 잠정안으로" 시도해보는 게 좋겠음 — anchoring bias 실험의 첫 데이터 포인트.
- **Tests-as-docs 철학이 명시화됨**. 테스트는 검증의 산출물이자 동시에 문서의 원천. `errorResponseFields()` 공유 helper 같은 보조 도구로 중복은 회피하되, 테스트 자체는 모두 문서화 대상.
- **review.md의 BEFORE/AFTER 라벨링이 anchoring 측정에 유효**. §1에 "AI가 처음 무엇을 제안했는지"가 보존되므로, 6 cycle 후에 "AI 잠정안 → 최종 결정"의 delta 패턴 분석 가능.
- **차기 task-context-flow Skill 개정 후보**: §5의 BEFORE/AFTER 컨벤션을 Skill에 박아 모든 review.md에 강제. 1 occurrence (now) — 다음 review.md에 같은 패턴 적용되면 count 2 → Skill 개정 후보.
