# Task Context

## Goal

`GET /posts` 엔드포인트로 게시글을 **페이지 단위로** 조회한다. 응답은 페이지 메타(`page, size, totalElements, totalPages`)와 콘텐츠 배열을 포함하는 단일 객체이며, 빈 페이지도 동일한 형식으로 반환한다. MVP의 두 핵심 기능(목록 조회 / 글 작성) 중 목록 조회 측.

## Background

`POST /posts`(2026-05-15)에 이어지는 MVP의 두 번째 핵심 기능. 작성된 글이 화면에서 보여야 게시판으로서의 최소 가치가 성립한다.

초안에서는 "페이지네이션을 MVP 범위 밖"으로 두려 했으나, **사용자 검토(2026-05-16)에서 페이지네이션 적용으로 결정 변경**됨. 자세한 경위와 결정 근거는 `2026-05-16-post-list.review.md` 참고. 이 작업이 끝나면 Week 2의 MVP 두 엔드포인트가 완성된다.

## Constraints

- **Security**: 인증·인가 범위 외. 응답에 PII·시크릿 없음. `size` 상한(100)으로 과대 응답 1차 방어.
- **Performance**: `findAll(Pageable)`은 페이지당 단일 SELECT + `count(*)` 한 번. 인덱스 추가 금지(POST 작업의 V1 인덱스 정책 유지) — `created_at` 인덱스 없이도 MVP 데이터 양에서는 수용 가능.
- **Operations**: Hibernate SELECT 로그가 `ORDER BY created_at DESC, id DESC LIMIT ? OFFSET ?`로 실행되는지 확인 (`format_sql: true`).
- **Compatibility**: 기존 `POST /posts` 계약·테스트는 그대로 통과해야 한다 (회귀 금지).
- **Time**: 학습 일정 내. 정확한 마감 없음.

## Acceptance Criteria

### 요청 파라미터
- `GET /posts?page={n}&size={m}`
- 기본값: `page=0`, `size=20`
- 유효 범위: `page >= 0`, `1 <= size <= 100`
- 범위 위반 시 → `400 Bad Request` + `ErrorResponse` (`code=VALIDATION_FAILED`, `errors[].field`에 위반 파라미터명 — `"page"` 또는 `"size"`)

### 성공 응답
- HTTP `200 OK`, 본문은 JSON 객체:
  ```json
  {
    "content": [ { "id": ..., "author": ..., ... }, ... ],
    "page": 0,
    "size": 20,
    "totalElements": 42,
    "totalPages": 3
  }
  ```
- `content` 배열의 각 항목은 `PostResponse`의 7개 필드 그대로
- 정렬: **`createdAt DESC, id DESC`** (page 간 안정성 보장)
- 빈 페이지: `200 OK` + `{ "content": [], "page": 0, "size": 20, "totalElements": 0, "totalPages": 0 }`
- 범위 밖 page 요청 (예: totalPages=3에서 page=99): `200 OK` + 빈 `content` (Spring 기본 동작 그대로)

### 부수 효과
- `viewCount`는 목록 조회로 **증가하지 않는다**
- 데이터베이스 상태는 변경되지 않는다 (`@Transactional(readOnly = true)` 권장)

### 회귀
- 기존 9개 테스트(init 1 + PostServiceTest 1 + PostControllerE2ETest 7)는 모두 통과

## Verification

- **Tests to run**:
  - `./gradlew test --tests "com.example.board.post.*"`
  - 전체 회귀: `./gradlew test`
- **Logs to check**:
  - Hibernate SELECT: `SELECT ... FROM posts ... ORDER BY created_at DESC, id DESC LIMIT ? OFFSET ?`
  - Hibernate COUNT: `SELECT COUNT(*) FROM posts ...` (페이지 메타용)
- **API/UI to check**:
  ```bash
  # 빈 상태
  curl -i "http://localhost:8080/posts"
  # 기대: 200 OK, body: {"content":[],"page":0,"size":20,"totalElements":0,"totalPages":0}

  # 글 두 개 작성 후
  curl -X POST http://localhost:8080/posts -H "Content-Type: application/json" \
       -d '{"author":"alice","title":"First","content":"Body1"}'
  curl -X POST http://localhost:8080/posts -H "Content-Type: application/json" \
       -d '{"author":"bob","title":"Second","content":"Body2"}'

  # 기본 페이지
  curl -i "http://localhost:8080/posts"
  # 기대: 200, content[0]은 "Second" (createdAt DESC), totalElements=2, totalPages=1

  # 커스텀 사이즈
  curl -i "http://localhost:8080/posts?page=0&size=1"
  # 기대: 200, content 길이 1, totalElements=2, totalPages=2

  # 범위 위반
  curl -i "http://localhost:8080/posts?size=101"
  # 기대: 400, body: {"code":"VALIDATION_FAILED", "errors":[{"field":"size", ...}], ...}
  ```

## Forbidden

- 새 의존성 추가 금지
- 새 Flyway 마이그레이션 추가 금지 (스키마 변경 없음)
- `sort` 쿼리 파라미터 지원 금지 — 정렬은 서버가 고정 (`createdAt DESC, id DESC`)
- `size > 100` 허용 금지
- `page < 0`, `size < 1` 허용 금지
- 검색·필터 파라미터 추가 금지 (`?author=`, `?q=` 등)
- `viewCount` 증가 로직 도입 금지
- N+1 쿼리 유발하는 연관관계 추가 금지
- 컨트롤러에 비즈니스 로직 작성 금지 (서비스로 위임)
- 필드 주입 사용 금지
- `application.yml`의 `ddl-auto` 변경 금지
- 인증/권한 도입 금지
- `BoardApplication`·`TestcontainersConfiguration`·기존 테스트(`BoardApplicationTests`, 기존 `PostControllerE2ETest`·`PostServiceTest`의 기존 메서드) 변경 금지
- 응답 record `PostResponse`의 필드 구성 변경 금지 (POST 응답과 계약 공유)
- Spring `Page<T>`를 그대로 JSON 직렬화 금지 — 반드시 `PageResponse<T>`로 매핑 (스펙 안정성)
